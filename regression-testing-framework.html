Automated multi-perspective testing for Salesforce products. Agent-executed. Failure-tracked. Quality-guaranteed.

4 Products 5 Perspectives 40+ Test Scenarios Auto-Ticketing

1. The Problem & Solution

Without This Framework

  • No systematic way to verify products work after updates
  • Past testing found ALL 3 products had blocking deployment failures
  • Bug fixes break existing features (undetected regressions)
  • Manual testing takes 20+ hours per release
  • No audit trail of what was tested and when
  • Failures discovered by clients, not by us

With This Framework

  • Every product has defined test scenarios (YAML files)
  • Claude agents execute tests automatically after changes
  • Failures auto-create OpenProject tickets with context
  • Testing drops from 20 hours to under 15 minutes
  • Full history of every test run with Markdown reports
  • Multi-perspective coverage: Dev, Admin, PM, Designer, Client

6. Agent Execution Workflow

Claude agents handle the entire test lifecycle - from execution to ticket creation.

1

User Triggers Test Run

"Run regression tests for Contact Duplicate Detection v2" or triggered by schedule/deployment

2

Mark Run "In Progress" in OpenProject

Creates task under Regression Testing epic with run timestamp

openproject-specialist
3

Execute 4-Layer Test Suite

Reads YAML test definitions, runs CLI commands layer by layer, records pass/fail for each test

salesforce-qa-specialist
4

Generate Results & Reports

Writes JSON results file + Markdown summary report with failure details, stack traces, coverage

salesforce-qa-specialist
5

Create Tickets for Failures

New regressions get HIGH priority tickets. Existing issues get comments. Flaky tests flagged after 3+ failures.

openproject-specialist
6

Fix & Rerun

Developer agent fixes the issue, deploys fix, reruns test suite to confirm resolution

salesforce-builder
